# simplified-python

> [!WARNING]
> **Experimental pre-release.** The subset is still being defined and is not ready for general use.
> Rule identifiers, statuses, and the registry format may change without notice between rule-set versions,
> and the checker enforces only the banned rules; restricted conditions still rely on human review.

A simplified subset of Python that is easy for humans to review.

Every program written in the subset is an ordinary Python 3.14 program with unchanged behaviour. The subset only removes or narrows Python constructs. It never adds syntax, and no transpiler or preprocessing step exists.

The subset is defined by the rule registry in [`subset/`](subset/). The human-readable reference, [`docs/subset.md`](docs/subset.md), is generated from that registry. See [`examples/`](examples/) for runnable programs written in the subset.

## The subset

Python is narrowed only where a construct makes code harder to review. Each narrowing cites one or more [review principles](docs/subset.md#principles): local reasoning, one obvious spelling, no action at a distance, and bounded reading cost.

Rule-set version 1 classifies every construct in the Python 3.14 grammar with 58 rules. 35 constructs are allowed without conditions. The rules below narrow Python. Each one links to its full entry, with rationale and examples, in [`docs/subset.md`](docs/subset.md).

### Banned

- [SP113](docs/subset.md#sp113) `no-template-strings`: Template string literals (PEP 750): `t"Hello {name}"`. *Instead:* Use an f-string to build text. To escape or quote values, call the escaping function explicitly on each value.
- [SP118](docs/subset.md#sp118) `no-walrus`: Assignment expressions (the walrus operator): `(match := pattern.search(line))`. *Instead:* Assign the value in its own statement on the line before, then use the name.
- [SP208](docs/subset.md#sp208) `no-global-or-nonlocal`: The `global` and `nonlocal` declarations. *Instead:* Pass the value in as an argument and return the new value. To keep shared state, put it in an object that is passed explicitly.
- [SP304](docs/subset.md#sp304) `no-loop-else`: An `else` clause on a `for` or `while` loop. *Instead:* Record the outcome in a variable inside the loop, then test that variable after the loop with an `if` statement.
- [SP502](docs/subset.md#sp502) `no-class-keywords`: Keyword arguments in a class header: `class A(metaclass=Meta)`, `class B(Base, flag=True)`. *Instead:* Write the behaviour as explicit methods or as module-level functions. To check subclasses, call a check function explicitly after the class is defined.
- [SP601](docs/subset.md#sp601) `no-star-import`: Importing every public name from a module with `from module import *`. *Instead:* Import the names you use explicitly, or import the module and qualify each name.
- [SP703](docs/subset.md#sp703) `no-except-star`: The `try` statement with `except*` clauses for exception groups. *Instead:* Catch the `ExceptionGroup` with a normal `except` clause and inspect its `exceptions` attribute explicitly.
- [SP801](docs/subset.md#sp801) `no-async`: Coroutines and asynchronous statements: `async def`, `await`, `async for`, `async with`. *Instead:* Write synchronous code. If concurrency is necessary, keep it outside code that must conform to the subset until async rules exist.
- [SP802](docs/subset.md#sp802) `no-async-comprehension`: An `async for` clause in a comprehension: `[x async for x in stream]`. *Instead:* Write synchronous code; see SP801.

### Restricted

- [SP110](docs/subset.md#sp110) `single-comparison`: A comparison: `a < b`, `x == y`, `key in table`. *Condition:* A comparison uses exactly one comparison operator. Chained comparisons such as `a < b < c` are not permitted.
- [SP114](docs/subset.md#sp114) `flat-conditional-expression`: A conditional expression: `a if condition else b`. *Condition:* The test and both branches of a conditional expression do not contain another conditional expression.
- [SP115](docs/subset.md#sp115) `starred-unpacking`: Starred expressions: `f(*args)`, `[*head, *tail]`, `first, *rest = items`. *Condition:* A starred expression may unpack values into a call or a list, tuple, or set display. It must not be an assignment target or a `for` loop target.
- [SP116](docs/subset.md#sp116) `lambda-as-argument`: Anonymous functions: `lambda item: item.size`. *Condition:* A lambda is permitted only as a direct argument of a call, such as `sorted(items, key=lambda item: item.size)`.
- [SP117](docs/subset.md#sp117) `simple-comprehensions`: List, set, and dict comprehensions, generator expressions, and their `for` / `if` clauses. *Condition:* A comprehension has exactly one `for` clause and at most one `if` clause, and contains no other comprehension.
- [SP203](docs/subset.md#sp203) `single-target-assignment`: Assignment: `total = 0`, `x, y = point`. *Condition:* An assignment has exactly one target, before a single `=`. Chained assignment such as `a = b = 0` is not permitted. Unpacking into one tuple target such as `x, y = point` is permitted.
- [SP405](docs/subset.md#sp405) `function-decorator-allowlist`: Decorators on a function or method: `@property`. *Condition:* Each decorator on a function is one of: `@property`, `@<name>.setter` or `@<name>.deleter` for a property defined in the same class, `@staticmethod`, `@classmethod`, or `@override` (imported from `typing`, or written as `@typing.override`). No other decorator is permitted.
- [SP406](docs/subset.md#sp406) `forwarding-varargs`: A variadic positional parameter: `def f(*args)`. *Condition:* A function may declare `*args` only if its body uses `args` only as `*args` in one call, passing the values on unchanged.
- [SP407](docs/subset.md#sp407) `forwarding-kwargs`: A variadic keyword parameter: `def f(**kwargs)`. *Condition:* A function may declare `**kwargs` only if its body uses `kwargs` only as `**kwargs` in one call, passing the values on unchanged.
- [SP408](docs/subset.md#sp408) `nested-functions-without-closures`: A function defined inside the body of another function. *Condition:* A function body may contain a nested `def` only if the nested function does not use any name that is a parameter or a local variable of the enclosing function.
- [SP503](docs/subset.md#sp503) `single-base-class`: The base classes listed in a class header: `class Child(Parent)`. *Condition:* A class lists at most one base class.
- [SP504](docs/subset.md#sp504) `class-decorator-allowlist`: Decorators on a class: `@dataclass`. *Condition:* The only permitted class decorator is `@dataclass` or `@dataclasses.dataclass`, written with or without keyword arguments, such as `@dataclass(frozen=True)`.
- [SP603](docs/subset.md#sp603) `shallow-relative-imports`: Relative imports: `from . import sibling`, `from ..package import name`. *Condition:* A relative import has at most one leading dot. Imports from parent packages use the absolute module path.
- [SP702](docs/subset.md#sp702) `typed-except-handlers`: An `except` clause: `except ValueError as error:`. *Condition:* Every `except` clause names the exception type or types it handles. A bare `except:` is not permitted.

## Checking code and teaching agents

The checker reports every banned construct with its file, line, column, rule and replacement. It exits 1 if it finds any. It does not verify the conditions on restricted rules, so those still need review. List them with `--restricted`.

```sh
uv run --python 3.14 skills/simplified-python/check.py src/    # files or directories
uv run --python 3.14 skills/simplified-python/check.py --restricted app.py
```

[`skills/simplified-python/`](skills/simplified-python/) is an agent skill that tells a model to write in the subset. It holds a digest of the banned and restricted rules, the full reference, a before/after example, and the checker, so the directory is self-contained. Copy or symlink it into your agent's skills directory, for example `~/.agents/skills/simplified-python`. It is generated from the registry, so do not edit it by hand.

## Development

Uses [uv](https://docs.astral.sh/uv/). uv installs Python 3.14 (pinned in `.python-version`) and the locked dependencies itself.

```sh
uv sync                                                 # create .venv and install dependencies
uv run python -m simplified_python.registry --check     # validate the registry
uv run python -m simplified_python.reference            # regenerate docs/subset.md and the README summary
uv run python -m simplified_python.skill                # regenerate skills/simplified-python/
uv run pytest                                           # run the tests
uv run examples/inventory.py                            # run an example
```
